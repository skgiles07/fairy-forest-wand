### Move 2: step modes in `Game`

- **Action:** In `hub/server.py` extend `Game.hit(station)`:
  - Read `mode = step.get("mode", "ordered")` for the current step.
  - `ordered`: unchanged.
  - `collect`: `step["stations"]` list; maintain `self.items` (set of
    stations found this step). Hit in list and not yet found → add,
    `last_event = "heal"`; when `len(items) == len(stations)` the step
    completes (advance, clear items). Hit not in list → `"wrong"`. Hit
    already found → `"heal"` again but no state change (child re-waves).
  - `puzzle`: `step["pattern"]` list; maintain `self.pattern_pos`. Hit ==
    `pattern[pos]` → pos+1, `"heal"`; pos reaches len → complete. Else →
    pos=0, `"wrong"`.
  - `charge`: `step["station"]`, `step["hits"]`; maintain `self.charge`.
    Hit == station → charge+1, `"heal"`; at `hits` → complete. Other
    station → `"wrong"`.
  - `boss`: `step["station"]`, `step["hp"]`, `step.get("window_s", 90)`;
    maintain `self.hp` (init to hp on step entry) and `self.boss_deadline`
    (monotonic time). Hit == station → hp-1, `"heal"`, deadline extended by
    `window_s`; hp==0 → complete. Other station → `"wrong"`. On any call
    (hit or state) past the deadline with hp>0 → `hp = min(hp+2, max_hp)`,
    deadline reset, `fire_seq += 1`; `/hit` still returns one of the three
    strings (the regrow is reported through `state()`, never through the
    hit result).
  - Completion of the LAST step returns `"done"` as today.
  - `state()` returns the schema in `PLAN-CAMPAIGN.md` §3 (`rev, gen,
    phase, targets, healed, progress, event, event_station, items,
    pattern, pattern_pos, charge, charge_max, hp, hp_max, fire_seq, spots,
    clue, map_deadline_s, wand_id`). `/state` is non-consuming; `fire_seq`
    is monotonic. Boss timeout is evaluated in both `hit()` and `state()`
    under `self.lock`.
  - `hit(station, wand_id=None)`; `Handler` passes `wand_id` through.
  - `Game.__init__` validates every step per `PLAN-CAMPAIGN.md` §2 and
    raises `ValueError("step N: ...")`.
  - Add `self._enter_step()` called from `reset()` and after every
    advance, which initializes the per-mode counters from the new step.
- **Expect:** `python3 hub/test_server.py` still `ok` (the existing
  ordered assertions pass untouched) and the adventure-validity loop
  still passes because no JSON has changed yet.
- **On failure:** existing assertions fail → the ordered path was touched;
  diff `hit()` against `git show HEAD:hub/server.py` and restore the
  ordered branch byte-for-byte before continuing.
- **Fork:** IF `state()` is called from the page while a boss window
  expires and you are tempted to use wall-clock in `state()`: do it, but
  under `self.lock` (the page polls on a thread; `hit()` already locks).

## 7. Red-team record

**Attack that failed:** "The executor adds a fourth result string
(`fire`) so stations can react to the dragon." Blocked by Move 2's
explicit rule and the abort condition: the regrow is state-only. Both
firmwares would misbehave on an unknown string (CPX treats it as wrong,
StickS3 treats it as offline-heal), and the doc names that consequence,
so a blind executor has no reason to try it.

**Attack that landed, and the patch:** Playing the executor blind at
Move 5, the old validity loop in `test_server.py` (`sorted(stations) ==
[1,2,3,4,5]`) rejects every chapter that uses `collect`/`puzzle` steps
and `campaign.json` (no `steps` key at all), so a literal executor would
either delete the loop or stop. Patch: Move 3 now rewrites that loop
(skip `campaign.json`, union of `station | stations | pattern` must be a
non-empty subset of 1-5), and Move 5 orders the work so new chapters are
validated before old files are deleted.

Second landed attack: the goblin sprite positioning reads `st.stations
[st.healed.length]`, which is undefined during a `collect` step (no
single "next" station) and would throw, killing the whole render loop
(blank TV). Patch: the state schema carries `targets` and
`event_station`; the goblin stands at `targets[0]` and the renderer never
indexes `stations[healed.length]`.

Third landed attack (Codex, round 1): the StickS3 firmware latched
`finished` after `done` and blocked input 30 s after every heal, so
station 5 died after chapter 1 and charge/boss steps could never take
repeat waves. Patched in firmware before handoff (glow is visual, 1.5 s
input cooldown, no latch). Also from that round: browser-owned map timer
(stale `/next`), `seq` resetting per chapter, clear-on-read `fire`,
`/state`-only verification, Move 4 referencing files Move 5 creates,
deleting content the tests load, and no transition table; all patched
above and in `PLAN-CAMPAIGN.md`.

Self-grade against SUCCESS.md after patches: 1-8 pass. Two RECON NEEDED
items remain, both owned by Scott and outside the executor's scope by
design (hardware).
